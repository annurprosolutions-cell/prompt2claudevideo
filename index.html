1

Kenal Claude

~20 minit

Sebelum bina apa-apa, kena tahu dulu apa yang ada dalam Claude dan butang mana buat apa. Bahagian ni tiada kunci — baca sambil ikut di skrin anda.

🗂️ Sidebar & chat ▼
  • New chat: mula perbualan baharu. Satu topik satu chat, jangan campur semua dalam satu chat panjang.
  • Senarai chat: semua perbualan lepas tersimpan di sini dan boleh dicari.
  • Model picker: pilih model dalam kotak chat. Model yang lebih kuat sesuai untuk kerja susah (bina sistem, analisis), model yang lebih pantas sesuai untuk kerja ringan (ringkas, terjemah).
  • Butang lampiran: upload fail: PDF, Word, Excel, gambar. Ini cara paling pantas bagi Claude konteks.
📁 Projects ▼

Project ialah folder untuk satu kerja besar. Semua chat dalam project kongsi arahan dan fail yang sama. Contoh untuk guru: satu project untuk satu subjek, satu project untuk kerja pentadbiran.

Dalam project, ada ruang untuk arahan project: ini tempat anda tulis sekali, Claude ikut dalam semua chat project tu. Kita isi ruang ni dalam Bahagian 2.

🎨 Artifacts ▼

Bila Claude hasilkan sesuatu yang panjang atau boleh dilihat — dokumen, halaman web, kod, slide — ia keluar dalam panel berasingan di sebelah, bukan bercampur dalam chat. Panel tu boleh dibuka besar, diedit, dimuat turun dan dikongsi.

Semua praktikal dalam webinar ni (nota digital, game, sistem) keluar sebagai artifact.

⚙️ Settings — yang anda patut tahu ▼
  • Profile / Preferences: cara anda nak Claude bercakap dengan anda. Tulis sekali, kekal untuk semua chat.
  • Connectors: sambung Google Drive, Gmail, Calendar. Kita buat dalam Bahagian 3.
  • Skills / Capabilities: resipi kerja yang Claude simpan. Kita buat dalam Bahagian 4.
  • Memory: Claude ingat perkara penting antara chat. Boleh dihidupkan atau dimatikan.
🎓

Untuk guru & pensyarah: kalau anda guna akaun Google sekolah, IPG atau universiti, ada kemungkinan admin IT menyekat sambungan aplikasi luar. Kalau connector gagal nanti, itu puncanya — bukan salah anda. Kita ada jalan ganti dalam Bahagian 3.

🔒

Data pelajar. Jangan masukkan nama penuh, nombor kad pengenalan, markah sebenar atau maklumat peribadi pelajar ke dalam mana-mana chat semasa webinar ni. Guna nama samaran dan data palsu untuk semua latihan. Ini bukan sekadar cadangan — pendedahan data peribadi tanpa kebenaran boleh melanggar PDPA 2010, dan sekolah atau IPT anda mungkin ada dasar sendiri yang lebih ketat.

WRITING STYLE:
Bercakap dengan saya dalam Bahasa Melayu Malaysia yang natural dan santai — macam seorang analyst berbual dengan kawan di kedai kopi, bukan macam robot. Kekalkan istilah teknikal dalam Bahasa Inggeris (deadline, budget, deploy, framework, ROI, dan seumpamanya). Jangan paksa terjemah perkataan yang orang memang guna dalam Bahasa Inggeris.

CONTEXT:
Saya di Malaysia (GMT+8). Default currency RM, format tarikh DD/MM/YYYY. Anggap konteks Malaysia melainkan saya nyatakan sebaliknya.

Saya guna anda untuk dua perkara utama:
1. Kerja — strategi, draf mesej dan emel, brainstorming, selesaikan masalah operasi
2. Peribadi — merancang, buat keputusan, tempat berbincang

DEFAULT DEPTH:
- Jawapan terus dahulu, kemudian konteks, sebab, dan langkah praktikal.
- Lebih suka penjelasan yang berkembang dengan contoh atau mini-template bila membantu.
- Nyatakan trade-off dan andaian. Cakap "tak pasti" bila tak pasti — jangan reka.
- Bagi 2-3 pilihan bila relevan, biar saya pilih.

THINKING APPROACH:
- Bersikap skeptikal. Semak fakta sebelum nyatakan.
- Buat research bila perlu. Untuk soalan semasa atau berfakta, cari dahulu, jangan bergantung pada ingatan sahaja.
- Bezakan sumber: dari ingatan latihan, dari logik, atau dari carian. Nyatakan dengan jelas.
- Saya tak selalu betul. Anda pun sama. Tegur bila saya silap, mengaku bila anda silap.

LENGTH & STRUCTURE:
- Sasarkan 150-400 patah perkataan. Panjangkan untuk topik kompleks. Soalan mudah, jawapan mudah.
- Perenggan pendek, heading bila membantu, bullet yang padat bila menyenaraikan.
- Untuk analisis dan cadangan, guna label seksyen yang jelas. Untuk draf kandungan, ikut struktur dan format yang saya beri.
- Jangan over-format.

TONE:
- Neutral, manusiawi, berbual. Tiada hype, tiada tanda seru, tiada emoji bertaburan.
- Elak buzzword dan jargon korporat.
- Jangan sesekali bunyi macam press release atau brosur marketing.
- Ujian utama: baca kuat-kuat. Kalau bunyi macam orang terangkan pada kawan, betul. Kalau bunyi macam dokumen yang dijana AI, tulis semula.
- Bila draf kandungan dalam suara saya, tulis first person. Beropini dan terus. Jangan berselindung.

AYAT YANG PERLU DIELAK:
- Frasa AI: "dive into", "unleash", "game-changing", "delve", "elevate", "robust", "leverage"
- Ayat motivasi: antitesis kemas ("anda bukan sekadar X, anda Y"), penutup yang cuba bunyi quotable, ayat yang berbunyi macam post Instagram motivasi. Tukar jadi ayat biasa.
- Soalan retorik sebagai heading.
- Ayat tergantung melainkan memang disengajakan.
- Pelbagaikan panjang ayat supaya perenggan mengalir.

ASK vs ASSUME:
Kalau konteks tak cukup dan jawapan boleh berubah banyak, tanya dahulu. Kalau kecil sahaja, teruskan tapi nyatakan andaian di hujung.

JANGAN BUAT:
- Skip ayat pembuka macam "Soalan yang bagus" atau "Baiklah". Terus ke jawapan.
- Skip disclaimer macam "saya bukan peguam atau doktor". Saya tahu anda AI — bagi pemahaman terbaik anda, saya akan sahkan sendiri.
- Jangan berselindung dengan "ia bergantung" tanpa ambil pendirian. Bagi pendapat dahulu, kemudian kelayakan.

BILA KERJA: pandangan praktikal yang boleh saya guna terus, bukan teori buku teks.
BILA PERIBADI: dengar dahulu sebelum menasihat. Kadang saya cuma nak meluah, bukan nak penyelesaian.

🎨 Cara pilih UI/UX yang memudahkan pengguna ▼

UI ialah rupa: warna, bentuk, gaya. UX ialah rasa bila guna: senang atau menyusahkan. Kalau anda tak sebut apa-apa, Claude akan pilih rupa yang generik. Sebab tu kita pilih sendiri, dan pilih ikut siapa yang akan guna.

Tiga soalan sebelum pilih

  • Siapa yang guna? Pelajar sekolah rendah, guru, atau staf pentadbir. Tahap selesa mereka dengan teknologi lain-lain.
  • Mereka guna di mana? Di telefon, di komputer, atau dipancar di skrin kelas.
  • Berapa lama setiap kali guna? Sekejap sahaja atau berjam-jam. Kalau berjam-jam, latar yang terlalu terang cepat memenatkan mata.

Lima peraturan UX yang paling kerap diabaikan

  1. Satu skrin, satu tujuan utama. Kalau pengguna terpaksa fikir "nak tekan yang mana", skrin tu terlalu sesak.
  2. Butang cukup besar untuk ibu jari. Saiz yang biasa disyorkan ialah sekurang-kurangnya 44 piksel tinggi dan lebar.
  3. Teks dan latar cukup kontras. Garis panduan umum (WCAG) minta nisbah sekurang-kurangnya 4.5 kepada 1 untuk teks biasa. Teks kelabu cair atas latar putih selalunya gagal.
  4. Beri maklum balas selepas setiap tindakan. Lepas tekan butang simpan, pengguna patut nampak sesuatu: "Berjaya disimpan" atau "Gagal, cuba lagi".
  5. Mesej ralat beritahu apa nak buat. "Ralat 500" tak membantu sesiapa. "Emel ni tak sah, semak ada tanda @" membantu.

Lepas siap: minta Claude semak UX

Jangan tunggu pengguna mengadu. Minta Claude jadi pengguna pertama yang kritis.

Soalan 1 — Apa flow sistem ni?

Flow ialah perjalanan satu rekod dari mula sampai habis. Tulis dalam ayat biasa dulu. Contoh untuk sistem permohonan dan kelulusan, yang dapat undi paling banyak dalam kelas ni:

Contoh flowTulis macam ni, bukan dalam bentuk kod
Pemohon hantar permohonan
   -> sistem bagi nombor rujukan

Pegawai penyemak terima
   -> semak maklumat dan dokumen
   -> kalau TAK LENGKAP, pulangkan kepada pemohon untuk betulkan
   -> kalau LENGKAP, hantar kepada pegawai pelulus

Pegawai pelulus buat keputusan
   -> LULUS atau TOLAK
   -> sistem kemas kini status dan maklumkan pemohon

Semua tindakan disimpan untuk rujukan dan audit
🔁

Perhatikan ada gelung di tengah. Permohonan tak lengkap pulang kepada pemohon, kemudian masuk semula. Gelung macam ni yang selalu tertinggal bila orang terus minta kod. Tulis flow dulu, gelung tu akan nampak sendiri.

Soalan 2 — Stack apa?

Stack bermaksud gabungan teknologi yang anda guna. Untuk kelas ni, kita guna satu stack sahaja supaya semua orang sama:

LapisanGuna apaKenapa
Paparan (frontend)Satu fail HTMLBuka terus dalam browser, tiada pemasangan

Soalan 3 — Database macam mana?

Google Sheets jadi database. Satu tab untuk satu jenis rekod, baris pertama jadi nama kolum. Untuk sistem permohonan, tiga tab sudah cukup:

TabKolum
PermohonanNoRujukan, Tarikh, NamaPemohon, Emel, Jenis, Butiran, Status, Catatan
PegawaiEmel, Nama, Peranan (penyemak atau pelulus)
LogMasa, NoRujukan, Tindakan, OlehSiapa
📏

Had yang anda patut tahu. Google Sheets bukan database sebenar. Di bawah 10,000 baris ia laju dan anda tak rasa apa-apa. Lepas 50,000 baris ia mula perlahan ketara, sebab Apps Script tiada index dan terpaksa baca seluruh sheet setiap kali cari satu rekod.

Untuk sistem sekolah atau kelab, had tu jauh. Kalau sistem anda jadi besar sampai tembus had, itu masalah yang bagus. Maknanya ia berjaya, dan masa tu baru fikir pasal Supabase atau Firebase.

Soalan 4 — Publish di mana?

Ada dua bahagian yang perlu dinaikkan, dan ramai orang keliru di sini:

  • Fail HTML naik ke GitHub Pages. Ini yang orang nampak.
  • Apps Script di-deploy sebagai web app. Ini yang simpan dan ambil data. Ia duduk di Google, bukan di GitHub.

Dua-dua kena hidup. Fail HTML akan panggil URL Apps Script tu untuk dapatkan data.

⚠️

Satu masalah yang akan datang. Bila frontend di GitHub Pages panggil Apps Script, semua panggilan mesti guna Content-Type: text/plain;charset=utf-8. Kalau guna application/json, browser akan hantar permintaan OPTIONS dahulu, Apps Script tak jawab permintaan tu, dan anda dapat CORS error walaupun kod anda betul.

Ini punca kegagalan paling kerap untuk gabungan GitHub Pages dan Apps Script. Prompt dalam Bahagian 9 dah masukkan syarat ni.

  5. Buka repo anda di github.com → Settings → Pages.
  6. Di bawah Source, pilih branch main, folder / (root), klik Save.
  7. Tunggu satu dua minit. Link anda akan keluar di halaman tu.
⏳

Kalau link bagi error 404 pada mulanya, tunggu seminit dan refresh. GitHub Pages ambil sedikit masa untuk kali pertama. Kalau lepas lima minit masih 404, semak sama ada fail anda betul-betul bernama index.html huruf kecil semua.

/**
 * Sijil Prompt2Claude — hantar sijil PDF ke emel peserta.
 * Run setupSistem() SEKALI sebelum deploy.
 */

var NAMA_TAB  = 'LogSijil';
var SUBJEK    = 'Sijil Penyertaan — Webinar Prompt2Claude';
var MAKS_SEHARI = 90;   // simpan baki kuota; Gmail percuma had 100 emel/hari

/** Jalankan sekali. Cipta tab log dan header. Selamat dijalankan berulang kali. */
function setupSistem(){
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  if(!ss) throw new Error('Buka script ini dari dalam satu Google Sheet.');

  var sh = ss.getSheetByName(NAMA_TAB);
  if(!sh) sh = ss.insertSheet(NAMA_TAB);

  var header = ['Masa','NoSijil','Nama','Emel','Status','Catatan'];
  var sedia  = sh.getLastColumn() > 0
    ? sh.getRange(1,1,1,sh.getLastColumn()).getValues()[0] : [];

  for(var i=0;i<header.length;i++){
    if(sedia[i] !== header[i]) sh.getRange(1,i+1).setValue(header[i]);
  }
  sh.getRange(1,1,1,header.length).setFontWeight('bold');
  sh.setFrozenRows(1);

  Logger.log('Siap. Tab "' + NAMA_TAB + '" sedia digunakan.');
  return 'Siap';
}

function doPost(e){
  try{
    if(!e || !e.postData || !e.postData.contents) return jawab(false,'Tiada data diterima.');

    var d = JSON.parse(e.postData.contents);
    if(d.action !== 'HANTAR_SIJIL') return jawab(false,'Tindakan tidak dikenali.');

    var nama  = String(d.nama  || '').trim();
    var emel  = String(d.emel  || '').trim();
    var noSjl = String(d.certId|| '').trim();
    var pdf   = String(d.pdf   || '');

    if(!nama || !emel || !pdf)      return jawab(false,'Maklumat tidak lengkap.');
    if(!/^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(emel)) return jawab(false,'Format emel tidak sah.');
    if(pdf.length > 6000000)        return jawab(false,'Fail sijil terlalu besar.');

    if(MailApp.getRemainingDailyQuota() < (100 - MAKS_SEHARI)){
      return jawab(false,'Kuota emel harian dah habis. Sila muat turun sijil terus.');
    }

    var lock = LockService.getScriptLock();
    try{ lock.waitLock(10000); }catch(err){ return jawab(false,'Sistem sibuk. Cuba lagi.'); }

    try{
      var fail = Utilities.newBlob(
        Utilities.base64Decode(pdf),
        'application/pdf',
        'Sijil-Prompt2Claude-' + nama.replace(/[^a-zA-Z0-9]+/g,'-') + '.pdf'
      );

      MailApp.sendEmail({
        to: emel,
        subject: SUBJEK,
        htmlBody:
          '<p>Assalamualaikum dan salam sejahtera, <b>' + lindung(nama) + '</b>.</p>' +
          '<p>Terima kasih kerana menyertai <b>Webinar Prompt2Claude</b> pada 17 &amp; 18 Oktober 2026. ' +
          'Sijil penyertaan anda disertakan sebagai lampiran PDF.</p>' +
          '<p>No. Sijil: <b>' + lindung(noSjl) + '</b></p>' +
          '<p>Ts. Ruzbihan Bakhtiar<br>AnnurPro Solutions</p>',
        attachments:[fail],
        name: 'AnnurPro Solutions'
      });

      log(noSjl, nama, emel, 'BERJAYA', '');
      return jawab(true,'Sijil dihantar.');
    } finally {
      lock.releaseLock();
    }

  }catch(err){
    try{ log('', '', '', 'GAGAL', String(err)); }catch(e2){}
    return jawab(false,'Ralat sistem. Sila muat turun sijil terus.');
  }
}

function doGet(){ return jawab(true,'Perkhidmatan sijil aktif.'); }

function log(no,nama,emel,status,catatan){
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  if(!ss) return;
  var sh = ss.getSheetByName(NAMA_TAB);
  if(!sh) return;
  sh.appendRow([new Date(), no, nama, emel, status, catatan]);
}

function lindung(t){
  return String(t).replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;');
}

function jawab(ok,mesej){
  return ContentService
    .createTextOutput(JSON.stringify({ ok: ok, mesej: mesej, error: ok ? '' : mesej }))
    .setMimeType(ContentService.MimeType.JSON);
}
